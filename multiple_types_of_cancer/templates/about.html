About This Project

What Multiple Types of Cancer actually does

A short walkthrough of the problem, the approach, and the results - for anyone reviewing this as a mini-project.

Cancer is the second leading cause of death worldwide, and early detection consistently improves outcomes. This project explores whether a single convolutional network can be trained to recognize four different cancer types - brain, breast, cervical, and lung - from CT/MRI style imagery, instead of building one narrow model per disease. The result is a working end-to-end system: a trained classifier wrapped in a small web application where anyone can upload a scan (or try a real sample from the dataset) and see a prediction with a full confidence breakdown.

Python Flask TensorFlow / Keras VGG19 Transfer Learning Bayesian Optimization Learning Without Forgetting HTML / CSS / JS

How it was built

  1. Data preparation - CT/MRI images for each cancer type were collected, cleaned, and split into training and test sets, then resized and normalized for the network.
  2. Transfer learning - a VGG19 network pretrained on ImageNet was used as the feature backbone, then fine-tuned on the four cancer classes instead of training a network from scratch.
  3. Bayesian hyperparameter optimization - learning rate, batch size, and layer-freezing depth were tuned automatically by searching for the configuration that generalized best, rather than guessing by hand.
  4. Learning Without Forgetting (LwF) - used during fine-tuning so the network adapts to the new cancer classes without erasing the general visual features it already learned from ImageNet.
  5. Deployment - the trained model was exported to .h5 and wrapped in this Flask application, so predictions run instantly from a browser with no separate setup.
  6. "Not a Scan" class - the original network could only ever answer with one of the four cancer types, even for a screenshot or a photo. A fifth class was added and the classifier head retrained on the four real cancer classes plus ~340 non-medical images (real photos and synthetic UI mockups), so the model itself now recognizes when an image isn't a scan at all.
